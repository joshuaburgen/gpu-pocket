# 手动深夜模式

监控页每张 GPU 卡片下方提供独立的“手动深夜（不避让）”按钮。它与控制页的自动策略分别管理，不需要打开自动管理、空闲自启或自动深夜模式。手动模式仍遵守北京时间 01:00–08:00 时段，并在 08:00 自动停止；它不受 25% 利用率或连续空闲 10 分钟条件限制。

本模式目前只支持已暂存的 SRBMiner Pearl 配置，按强度 31 启动。已有矿工运行时，确认开启会重启该卡的受管矿工。Python、CARLA 等其他任务不会被停止；手动深夜矿工会与其共用 GPU，可能影响双方性能或导致显存竞争。

## 使用方式

1. 在控制页为目标 GPU 保存 Pearl 算法、矿池与钱包。
2. 回到监控页，点击该卡的“手动深夜（不避让）”，阅读资源争用说明并确认。
3. 运行中卡片显示蓝色，按钮变为“停止手动深夜”。停止会退出手动模式并交回原有自动策略；若自动策略仍开启且条件满足，自动策略可能再次启动矿工。

运行中关闭自动管理不会退出手动深夜模式；北京时间到达 08:00 时，服务端会自动停止矿工并退出手动模式，即使每卡自动管理或全局 `control_enabled` 已关闭。若系统在 08:00 时离线，恢复后下一轮策略检查会补执行退出。

CPU 也提供监控页快捷手动深夜控制，使用已暂存的 CPU 配置并在北京时间 08:00 自动停止，不要求开启 CPU 自动控制。CPU 自动控制另有低负载自启（整机 CPU 使用率低于 25% 连续 10 分钟）和自动深夜模式（01:00 启动、08:00 停止）；这些开关默认关闭。CPU 的 SRBMiner 线程比例是工作线程提示，不是系统级硬限额。

执行自动指令前，服务端会在操作锁内重新检查模式；手动接管前已经排队的自动停矿、自动重启指令不能覆盖手动深夜。显存保护停矿使用独立标记，仍可停止当前手动会话。

## 显存保护

启动前检查该卡最低可用显存设置，默认 2048 MiB。不足或无法采样时拒绝启动。运行中每轮策略检查继续检查显存，即使该卡自动管理关闭也保留此保护。

显存不足、显存指标缺失或 GPU 消失时，停止受管矿工并保留 `manual_night` 模式选择。恢复显存后不会自行重启，也不会让自动策略接管，需点击按钮手动重启，或点击“退出手动模式”交回自动策略。

服务端和矿工同时使用既有显存保护设置；服务端轮询约每 5 秒一次，属于停矿保护，不是显存硬上限，无法保证轮询间隙内不发生 OOM。

## API 与状态

`GET /api/v1/catalog` 返回 `manual_night_supported: true` 表示服务端支持该模式。`POST /api/v1/gpus/{gpu_id}/miner` 接受模式 `manual_night`；切换运行中的模式应使用 `restart`，而不是对已运行服务重复调用 `start`。

```json
{"operation":"restart","revision":1,"mode":"manual_night"}
```

`revision` 必须取该卡当前已暂存配置的版本。显存不足或无法采样返回 409，且不提前写入新的运行模式。该模式不进行外部计算进程排他检查，不修改每卡自动策略配置。监控接口在 `policies` 中返回 `mode: "manual_night"`，通过 `runtime.memory_blocked` 区分显存保护暂停。

用户调用 `stop` 后模式回到 `normal`；显存保护内部调用的 `stop` 保留 `manual_night`，用来防止自动恢复或自动策略重新接管。

## 部署与回滚

新模式需要新版 API 和客户端一起使用。旧版 API 不能解析持久化的 `manual_night`，因此回滚到旧版前，应先通过新版 API 或 App 停止并退出两张卡的手动模式，确认模式为 `normal`；仅用 systemctl 停止矿工不会清除模式选择。

验证使用模拟矿工和可控 GPU 指标，覆盖不避让外部任务、自动管理开关、08:00 到期退出、显存不足拒绝启动、指标缺失停矿和恢复显存后不自启。没有为了测试而在真实训练、模拟任务旁启动矿工。
